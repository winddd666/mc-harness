## 本轮修改

- `harness/mc_tools.py`：`mc_status` 按实际距离检查最多 5 只近敌，返回 `nearby_hostiles`、检查数量和检查是否完整。`hostile_blocked_by_wall` 继续只指向状态中指定的最近实体；无法确认时为 `null`。射线遮挡不再产生 `safe_in_place=true`。有顶仅说明上方存在遮盖。兼容 API 实际使用的 `spawn` 重生事件。
- `harness/agent.py`：同步修正系统提示；将开局快照写入 `run.started.initial_snapshot`，将实际送给模型的期间事件写为独立 `mc.notable_events`，带对应 `call_id`。
- `live/state.py`：直接消费上述事件生成状态补丁和 `game_events` 帧；支持死亡清空背包、重生位置和生命恢复；保留旧日志的伴随报告兜底，新日志不会重复应用伴随事件；保护已经由重生后背包查询确认的物品。
- `live/static/app.js` 与 `console/server.py`：展示独立游戏事件并更新原工具卡片，不增加重复工具执行记录。
- `live/server.py`：mc-live 首次接入先分页追平所有历史事件，再进入实时告警。每次最多 10 页，未读完时下次继续初始化。实时阶段同样分页处理，兼容旧响应缺少 `has_more` 的情况。

这些修改提高观测完整性和威胁判断准确度，尚未经过实机运行验证，不能视为已经解决了死亡循环。
